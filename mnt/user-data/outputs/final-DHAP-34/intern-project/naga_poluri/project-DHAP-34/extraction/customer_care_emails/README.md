# customer_care_emails Pipeline

**Project:** DHAP-34 | **Author:** naga_poluri
**Repo:** https://github.com/The-Nagaa/airflow-dag-configs

This pipeline loads the customer_care_emails CSV into a PostgreSQL table
using Apache Airflow running in Docker. It validates the data first,
cleans it, then loads it.

---

## How It Works

```
CSV file (downloaded from SharePoint)
    ↓
placed in sample_data/
    ↓
Airflow DAG triggers
    ↓
file_check → validate_schema → transform → create_table → load_to_postgres
    ↓
data is in public.customer_care_emails ✅
```

## Environment Variables

```bash

```

| Variable | Description |
|----------|-------------|
| `PG_HOST` | postgres host (use `target-db` when running in docker) |
| `PG_PORT` | postgres port, default 5432 |
| `PG_DB` | database name |
| `PG_USER` | postgres username |
| `PG_PASSWORD` | postgres password |
| `AIRFLOW__CORE__FERNET_KEY` | fernet key for airflow |
| `AIRFLOW_WEBSERVER_SECRET_KEY` | secret key for airflow webserver |

> Never commit `.env` to Git. Only `.env.sample` is safe to commit.

## Running the Pipeline

**Step 1** — put the CSV in the right place:
```
extraction/customer_care_emails/sample_data/customer_care_emails.csv
```

**Step 2** — start docker:
```bash
cd airflow-dags/naga_poluri-project1
docker compose up -d
```

**Step 3** — go to Airflow UI at http://localhost:8080 (admin / admin)

**Step 4** — find the DAG `customer_care_emails_ingest`, turn it on and click Trigger

**Step 5** — verify the data loaded:
```bash
docker exec -it target_postgres_db psql -U pg_user -d customer_db

SELECT COUNT(*) FROM public.customer_care_emails;
SELECT id, email_subject, issue_type, sentiment_label FROM public.customer_care_emails LIMIT 5;
```

## DAG Tasks

| Task | What it does |
|------|-------------|
| `file_check` | makes sure CSV exists and is not empty |
| `validate_schema` | checks CSV columns match schema_expected.yaml |
| `transform` | strips whitespace, skips status=done rows, fixes nulls |
| `create_table` | creates the postgres table if it doesnt exist yet |
| `load_to_postgres` | inserts clean rows using ON CONFLICT DO NOTHING |

> Rows with `status = 'done'` are skipped automatically in the transform step.

## Troubleshooting

**CSV not found error**
Download the file from SharePoint and place it in `sample_data/`

**Schema mismatch error**
Check your CSV column headers match the ones in `schema_expected.yaml`

**Can't connect to postgres**
```bash
docker ps  # check target-db is running
docker compose restart target-db
```
Also double check your `.env` values are correct.

**DAG not showing in Airflow**
There's probably a syntax error in the DAG file. Run this to check:
```bash
docker exec -it airflow_scheduler python \
  /opt/airflow/extraction/customer_care_emails/dags/customer_care_emails_ingest.py
```

**Rerun a failed task**
Airflow UI → Grid View → click the failed task → Clear → Confirm

**Reload all data from scratch**
```sql
TRUNCATE TABLE public.customer_care_emails;
```
Then trigger the DAG again.

## Updating the Schema

If the dataset adds new columns:

1. Add the column to `config/schema_expected.yaml`
2. Add it to `config/create_table.sql`
3. If the table already exists, run manually:
   ```sql
   ALTER TABLE public.customer_care_emails ADD COLUMN new_col TEXT NULL;
   ```
4. Test by triggering the DAG end to end
5. Commit the changes

---

## New CSV Drop

When a fresh CSV comes from SharePoint:

1. Replace `sample_data/customer_care_emails.csv`
2. Make sure column headers haven't changed
3. Trigger the DAG
4. Check row count in postgres to confirm
